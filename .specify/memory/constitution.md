# Virel AI Constitution

## Core Principles

### I. Native Client Acceptance
An integration is accepted through the actual native node/SDK/agent, without custom client glue being counted as compatibility. Record version, operation, actual UI model, input and outcome. Mocks are necessary regression checks, not live certification.

### II. Incremental Delivery Without Regressions
One agreed feature and branch, with spec/plan/tasks and verifiable acceptance. Preserve earlier checks; do not suppress failures or weaken contracts to obtain green results.

### III. Clear Boundaries and Honest Capabilities
Separate HTTP shapes, input conversion and browser actions. No empty future modules. Models/capabilities must actually exist. Errors are errors; token counts require provenance and accuracy, not invented usage.

### IV. Explicit History and Isolation
Full-history clients replay context once in a fresh chat. Delta-only clients require isolated session IDs/reset/expiry. The inherited shared continuous tab is not a session implementation.

### V. Private Runtime and Clear Documentation
Keep account profiles, secrets, uploads and runtime records out of Git/build contexts. Validate input trust boundaries before accepting media. Use concise English public documentation and ordinary Markdown. Explain progress to the user in Egyptian Arabic.

## Scope and Constraints

Start with AI Studio and expand adapters incrementally. Website/account/model limits remain documented constraints. Inherited foundation defects are recorded exceptions, not repaired by writing principles. Stage 002 addresses text readiness/errors/usage; later media/history gaps remain scoped to their stages.

## Development Workflow

Official Spec Kit: specify → plan → tasks → implement → converge → checks → native evidence → review → PR → merge/tag. Feature artifacts live in `specs/<feature>/`. Never infer authorization for the entire roadmap from a single document command. The user has now authorized starting stage 002.

## Governance

Record user-directed amendments with version/date and update dependent documents. Version 1.0.1 adopted Virel AI branding and removed forced RTL. Version 1.0.2 adopts English public documentation and authorizes stage 002.
